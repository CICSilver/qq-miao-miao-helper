# QQ喵喵助手 · PC 版（QQNT 插件）

**发送那一刻才改写**——输入框里始终是你自己打的原文，按下发送才变成喵化版本。
这是安卓版做不到的：无障碍服务拦不住发送动作，而 QQNT 是 Electron，发送调用可以直接拦。

```
你在输入框里看到的：  我今天下班早，你要不要一起吃饭
实际发出去的：        本喵今天下班早，主人要不要一起吃饭喵
```

## 安装

需要 [QwQNT](https://qwqnt-community.github.io/) 或 LiteLoaderQQNT（后者已于 2026-05 归档，
但可作为插件运行在 QwQNT 内）。

把 `pc-qqnt/` 整个目录复制到插件目录并重命名为 `qq_miao_nt`：

```
<QQ数据目录>/plugins/qq_miao_nt/
├── manifest.json
├── src/
│   ├── engine.js
│   ├── preload.js
│   ├── renderer.js
│   └── main.js
└── tools/
```

重启 QQ，在 设置 → 扩展 里就能看到「QQ喵喵助手」。

## 原理

QQNT 渲染进程通过 `ipcRenderer.send('IPC_UP_<winId>', meta, [cmdName, params])`
把调用送到主进程。发消息走的是 `cmdName` 含 `sendMsg` 的那条，参数里带着
`msgElements` 数组。插件在 `send` 真正发出之前，把其中的文本元素改掉。

两条硬性设计原则：

1. **绝不抛异常。** 钩子挂在发消息的主路径上，它崩了等于 QQ 发不出消息。
   所有逻辑包在 try/catch 里，出任何问题都放行原始调用。
2. **不写死 payload 下标。** 用深度搜索找 `msgElements`，而不是
   `args[1][1].msgElements`。QQ 版本一变下标就废。

`@某人` 在 NTQQ 里也是文本元素，靠 `atType` 字段区分——带 `atType` 的一律跳过，
否则 @ 会失效。

## 如何暂停 / 彻底停用

**暂停**：设置面板最上方的「启用」开关，关掉立刻生效，不用重启 QQ。

**彻底停用**（任选其一）：

- 用**原版方式**启动 QQ，不经过 QwQNT 注入器。QwQNT 是「即用即插」的 ——
  不注入就完全不加载任何插件，QQ 干干净净。
- 删除插件目录 `plugins/qq_miao_nt/`，重启 QQ。
- 在 QQ 的扩展列表里禁用本插件。

**卸载 QQ 没有用。** 插件装在 QwQNT / LiteLoader 的**数据目录**里，不在 QQ 的
安装目录下。卸载 QQ 不会删掉它，重装 QQ 再用注入器启动，插件还在那儿。
要清理干净就删插件目录，或者干脆别用注入器启动。

## 钩子没生效怎么办

QQ 的内部通道名会随版本变。设置面板里打开**调试**开关，发一条消息，
下面会列出经过的所有 `cmdName`：

- 看到含 `sendMsg` 的调用但消息没被改 → payload 结构变了，把日志贴出来
- 完全看不到 `IPC_UP_*` → 通道命名变了，需要调整 `src/preload.js` 里的 `IPC_UP` 正则

改写点集中在 `preload.js` 的 `rewriteElements()` 和 `findMsgElements()` 两个函数里，
其余代码不用动。

## 与安卓版的区别

PC 版只在发送时变换一次，所以安卓版里那堆麻烦事在这里统统不存在：

| 问题 | 安卓版 | PC 版 |
|---|---|---|
| 幂等性 | 需要（每敲一个字重写一次） | 不需要 |
| 自指规则套娃 | 需要追踪用户原文 | 不可能发生 |
| 拼音组词冲突 | 需要启发式规避 | 不存在 |
| 发送时机 | 拦不住，只能保证「随时已喵化」 | 精确拦截 |

引擎本身的保护区逻辑两边一致：URL、邮箱、`@提及`、`[表情]`、反引号代码都不会被破坏，
纯链接消息原样放行。

## 验证状态

```bash
node --test tools/engine.test.mjs tools/hook.test.cjs
```

40 个用例，覆盖：

- **引擎**（23 个）：保护区、语气词位置、单趟最长优先替换、概率与限流、边界输入
- **钩子**（17 个）：把 `electron` 换成假模块后完整跑一遍拦截逻辑，包括
  @提及不被改写、非文本元素不被碰、非 sendMsg 调用放行，以及三个健壮性用例
  （畸形 payload、循环引用、引擎抛错）——确认这些情况下消息**照常发出**。

**没有验证的部分**：真实 QQ 的 IPC payload 形状是否与测试里构造的一致。
测试用的是社区文档描述的结构，但只有装到你的 QQ 上才能确认。
第一次用请先开调试模式发一条消息看看。

## 风险

修改 QQ 客户端行为违反腾讯用户协议，QQ 安全中心可能将此类插件判定为外挂，
后果包括设备下线乃至封号。自用请酌情，不建议分发，也不要在此基础上做自动回复、
批量发送这类明显越界的功能。
